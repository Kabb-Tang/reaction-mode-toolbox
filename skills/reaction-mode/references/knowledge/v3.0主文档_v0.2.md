## 一、v3.0 是什么

**v3.0 反应模式工作坊** 是基于《内在转化理论框架》构建的**实操系统**,核心任务是帮助用户**减少反应模式的发生**。

形态:**双入口共享底层** —— 用户既可以从场景化工具(被触发了 / 想做冥想 / 想记日志)进入,也可以从训练路径(系统训练识别力 / 穿透力 / 选择力 / 建设力)进入,两个入口共享同一套底层构件。

不是什么:

- 不是理论框架的简版或概览
- 不是"内在转化"整体的实操化
- 不是诊断和治疗系统
- 不是替代水老师一对一工作的产品——是工作之间和之外的支撑

## 二、v3.0 的核心轴:减少反应模式

v3.0 的所有构件、所有训练、所有 agent 行为,都围绕同一个核心轴:**减少反应模式的发生频率和强度**。

任何不在这个核心轴上的内容——即使本身有价值——都不纳入 v3.0。这是 v3.0 区别于"理论框架整体实操化"的根本边界。

**核心轴的关键特性:**

- **减少不等于消除** —— 理论框架 3.8 明确反应是正常的,目标是减少而不是消除
- **减少要通过底层处理实现** —— 不是行为压抑,是底层感受被允许流动后,反应的根松动了
- **核心轴本身是悖论的源头** —— "减少反应模式"作为目标会被反应模式机制接管。详见 v3.0 元规则第二章

**核心轴的实操化路径:**

```
识别(看见反应) → 穿透(下到底层感受 + 接受) → 选择(让涌现回应被跟随)
   ↑                                                    ↓
   └──── 螺旋上升,不是单向线性 ──────────────────────┘
```

这是 v3.0 实操化的**事后路径** —— 反应模式发生了,通过觉察 / 穿透 / 选择来减少其再次发生。模块一二三在这条路径上展开。

但这不是 v3.0 实操化的全部。

### 实操化的两条路径

理论框架第三章前置说明立住了**觉察工作和建设工作并列**。这意味着 v3.0 的实操化也有两条路径:

**路径一(事后路径,觉察主导):** 反应模式已经发生,通过觉察 / 穿透 / 选择减少其再次发生。**模块一二三**在这条路径上。

**路径二(前置路径,建设主导):** 反应模式还没被外部消极话术、攻击性定义、诅咒式预设触发之前,建立内在结构让这些外部输入不容易自动着陆。**模块四**在这条路径上。

两条路径**不互相替代**:

- 觉察工作处理已经存在的反应模式 —— 看见 + 允许 + 让感受流动
- 建设工作处理还没被反应模式接管的内在结构 —— 反复确认 + 累积 + 不被覆盖

**反应模式真正的减少需要两条路径配合。**

错配会出真实问题:把建设工作误用觉察方法,用户陷入"看清了但不能动";把觉察工作误用建设方法,觉察变成新的对抗。

判据和错配处理详见元规则文档第四章。

## 三、v3.0 的整体架构

### 3.1 双入口结构

```
┌─────────────────────────┐    ┌─────────────────────────┐
│   场景入口(工具视角)    │    │   训练入口(模块视角)    │
│                         │    │                         │
│  • 工具 A:被触发了      │    │  • 模块一:识别力训练    │
│  • 工具 B:想做冥想      │    │  • 模块二:穿透力训练    │
│  • 工具 C:想记日志      │    │  • 模块三:选择力训练    │
│                         │    │  • 模块四:建设力训练    │
└─────────────────────────┘    └─────────────────────────┘
            │                              │
            └──────────────┬───────────────┘
                          ↓
            ┌─────────────────────────────┐
            │   共享底层(三层结构)        │
            └─────────────────────────────┘
```

**双入口不是双产品** —— 工具和模块在底层共享同一套理论、同一套核心载体(工具 C 是模块一载体、工具 A 第二段是模块二的急性载体、内在确信感的日常练习是模块四的核心载体等)、同一套防滑精神。

用户从哪个入口进入都能到核心工作位置:

- 场景入口适合**当下有具体需要**的状态(被触发、想冥想、想记)
- 训练入口适合**想要系统建立能力**的状态(想练识别 / 穿透 / 选择 / 建设)

**很多用户两个入口都用** —— 平时通过工具 C 持续记录(场景入口),同时按模块一阶段做识别训练(训练入口),两者天然互通。

### 3.2 三层结构

```
┌────────────────────────────────────────────────────────┐
│  根基层 (long-term foundation)                          │
│  - 工具 B(冥想路由器)—— 日常身心容量培养              │
│  - 模块一身体进入练习 —— 身体居住能力                    │
│  - 模块一情绪命名 —— 情绪粒度培养                        │
│  - 模块四内在确信感的日常练习 —— 内在结构建设            │
├────────────────────────────────────────────────────────┤
│  反应中工作 (in-the-moment work)                        │
│  - 工具 A(三模块:急性止血 / 缓冲处理 / 后续复盘)       │
│  - 模块一身体信号识别(预警)                            │
│  - 模块二日常深潜接受 / 接受微练习                       │
│  - 模块三候选观察 / 质感识别                             │
│  - 模块四不被自动覆盖的体验积累 / 三步顺序               │
├────────────────────────────────────────────────────────┤
│  反馈闭环 (feedback loop)                               │
│  - 工具 C(反应日志)—— 日常持续记录                    │
│  - 月度回看 —— 各模块各自的视角                          │
│  - 诊断路径 —— Agent 内部的判断框架                      │
└────────────────────────────────────────────────────────┘
```

**三层不是顺序,是并行运作的不同层面。** 用户在任何阶段同时在三层中工作——根基在累积、反应中工作在发生、反馈在闭环。

### 3.3 四个模块的结构关系

```
事后路径(觉察主导):
模块一:识别力训练
   ↓
模块二:穿透力训练         模块四:建设力训练
   ↓                       (前置路径,建设主导)
模块三:选择力训练               
   ↓                              ↓
螺旋上升回到模块一            参照点的反复维护
   (下一层)                  (反复回来)
```

**模块一二三是事后路径的递进**(觉察主导):

- 模块二要求模块一至少在阶段二(事后几小时能识别)
- 模块三要求模块一至少在阶段三 + 模块二至少在阶段二三

依赖不是死锁——同时做也行,但前面没到位时后面会卡。

**模块四是前置路径**(建设主导):

- 模块四不是模块三之后的"更高阶",**是和模块一二三并行运作的另一条路径**
- 模块四有一个硬前提:模块二至少在阶段二(理由:建设过程中会反复升起被外部话术覆盖时的核心感受,这些核心感受没被穿透接受过,建设动作会被它们接管)
- 模块四不是模块一二三的替代品,是它们的补充。两条路径配合,反应模式工作才完整

模块一二三的**不是阶段考试**精神在模块四同样适用——能力标志才是关键,不是练了多久。

## 五、命名约定

v3.0 在分批起草过程中产生了一些命名,需要在主文档统一处理。这一章是命名约定的权威参考。

### 5.1 路径概念的两种含义

"路径 A / 路径 B"这两个标签在 v3.0 不同文档里有**两种完全不同的语义**,必须区分:

**语义一:身体通道强弱(主用法)**

在工具 A、工具 B、模块一二三、模块四、个性化分支中,"路径 A / 路径 B"指**身体通道敏感度**:

- **路径 A** = 强身体通道(默认)—— 通过身体感受做工作
- **路径 B** = 弱身体通道(心盲症 / 感觉钝化 / 严重述情障碍)—— 通过语言/认知做同样工作

**重要:路径 B 不是路径 A 的降级备选**,是独立有效的路径,只是走的通道不同。

**语义二:诊断路径的分流(只在诊断路径文档使用)**

在诊断路径文档中,跨场景诊断的 5 条分流路径**已改名**避免冲突:

- **急性分流** = 工具 A 第二段(止血)
- **触发分流** = 工具 A 第二段 / 工具 B(根据状态)
- **反思分流** = 陪伴看见
- **训练引导分流** = 引向训练路径
- **训练诊断分流** = 进入层二训练诊断

### 5.2 四大模块阶段命名

模块一二四的阶段命名采用植物隐喻(暗示自然生长 + 螺旋反复):

| 模块 | 阶段一 | 阶段二 | 阶段三 | 阶段四 |
|---|---|---|---|---|
| 模块一 | 识别的种子期 | 识别的萌芽期 | 识别的开花期 | 识别的成熟期 |
| 模块二 | 穿透的种子期 | 穿透的萌芽期 | 穿透的开花期 | 穿透的成熟期 |
| 模块四 | 建设的种子期 | 建设的萌芽期 | 建设的开花期 | 建设的成熟期 |

**模块三的阶段命名当前用特征化命名**(候选盲/候选可见/质感分辨/自由涌现),计划在模块三 v0.3 时改为植物隐喻:

- 阶段一:**选择的种子期** (原:候选盲)
- 阶段二:**选择的萌芽期** (原:候选可见)
- 阶段三:**选择的开花期** (原:质感分辨)
- 阶段四:**选择的成熟期** (原:自由涌现)

### 5.3 工具 B 状态编号

工具 B 的 7 种状态在所有引用它的文档中编号一致:

| 状态 | 名称 | 关键特征 |
|---|---|---|
| 状态 1 | 情绪洪水 / 思维过载 | 被淹没,无法静下来 |
| 状态 2 | 抗拒感强烈 / 对现实不接纳 | 推开,不允许 |
| 状态 3 | 头脑停不下来 / 过度反刍 | 思维循环 |
| 状态 4 | **急性创伤激活** / 身体强烈紧绷 | **不自助,转介水老师** |
| 状态 5 | 反复反刍过去 / 困在旧场景 | 内在小孩需要重新养育 |
| 状态 6 | 空洞感 / 存在感薄弱 | 解离倾向 |
| 状态 7 | 一般性日常练习 / 没有特定触发 | 维持性 |

**每种状态有路径 A(强身体通道)和路径 B(弱身体通道)对应的冥想推荐。** 详见工具 B 文档。

### 5.4 三个不同时间尺度的反应模式概念

避免混淆,显性建立:

| 时间尺度 | 概念 | 在 v3.0 里的位置 |
|---|---|---|
| 年/十年 | **生存策略** | 个性化分支 · 按生存策略的冒险方向 |
| 触发时(秒/分钟) | **反弹主导类型** | 个性化分支 · 按反弹主导类型的训练重点 |
| 反应中(过程性) | **情绪化小孩 vs 脆弱小孩** | 整体散见各模块 |

### 5.5 模块四的简称

沿用"模块四",不另起短名(和模块一二三体例一致)。完整名"模块四:建设力训练",日常引用"模块四"。

### 5.6 不妖魔化抗拒的引用形式

v3.0 文档内部统一使用短名"不妖魔化抗拒",这是稳定命名(不别名、不缩写,不"嵌套接纳""递归接受"等)。需要详细引用理论章节时,再用全称"理论框架 4.9 不妖魔化抗拒小节"。

### 5.7 觉察工作 / 建设工作

理论框架第三章前置说明立的两类工作类别。v3.0 文档内部统一使用全称("觉察工作""建设工作"),不缩写为"觉察""建设"单独使用 —— 单独使用会和"觉察"作为动作 / "建设"作为日常动词混淆。

### 5.8 内在稳定参照点

理论框架 5.6 章节立的概念,定义为"不依赖外部反馈维持的内在结构"。模块四的核心工作对象。v3.0 文档内部直接使用,不别名为"内在锚点""内在确信"等。

## 七、v3.0 的元规则

v3.0 的所有具体执行都受三条元规则支配。详见《v3.0 元规则 · 悖论、完成感、觉察 vs 建设》文档。

### 元规则一:减少反应模式悖论的接受

> v3.0 的设计假设是悖论会反复发作,而不是悖论可以被解决。

具体来说:

- "减少反应模式"作为目标会被反应模式机制接管(用应该/必须的紧的姿态追求减少反应模式)
- 这个悖论无法通过更好的设计完全避免
- v3.0 的工作不是避免悖论,是反复识别悖论的发作 + 不让它毁掉训练
- **检测方法:** 看做训练时身体的质感(松还是紧),不看做了什么

### 元规则二:不存在"练完",但存在"告一段落"

> v3.0 没有"练完",但有真实的"告一段落"。

具体来说:

- 反应模式工作是螺旋的、神经系统层面的,不是任务清单
- 但用户的真实体验里会出现"完成感",这是真实的
- 三种完成感的区分(详见元规则文档第 3.3):
  - **健康的完成感** —— 某一层的告段落,认可
  - **中性的完成感** —— 累了,建议暂停而非停止
  - **危险的完成感** —— 头脑判断/逃避,慢动作处理

### 元规则三:任何工作中升起的反应,可以作为新对象

> v3.0 的任何工作(觉察 / 建设 / 元层判断)中,都会升起新的反应:对工作本身的抗拒、对自己"又没做好"的自责、对工作机制的怀疑等。

这些升起的反应,不是工作失效的证据,**是工作在元层的延伸**。处理方式统一 —— 把每一个新升起的反应**当作新的对象**,承认它在这里,允许它在身体里。如果再有新东西升起,继续把新升起的当作新对象。

这就是不妖魔化抗拒机制(理论框架 4.9)在 v3.0 整体的应用。它在三个具体场景里被显性化(详见元规则文档):

- 悖论发作时升起的反应("我又把它当应该了")
- 完成感处理过程中升起的反应(被指出逃避后的羞耻 / 自责)
- 觉察 vs 建设错配时升起的反应(看见自己用错方法之后的失望 / 评判)

这三个场景共享同一个机制 —— 看见 → 不评判 → 把升起的当作新对象 → 继续。

这个机制是 v3.0 整体的兜底 —— 当上面两条元规则也失效时,启用这一条。

---

**三条元规则的共同解药:**

> 回到当下的具体体验,而不是抽象的目标和评判。

具体来说:

- 元规则一的解药:看当下做训练时身体的质感(松/紧)
- 元规则二的解药:看具体的反应模式 / 内在结构现在是什么状态
- 元规则三的解药:把当下升起的当作新对象,不追求"完成处理"

这是 v3.0 在所有层级一致的核心姿态。

## 九、对终端用户的意义

(本节为有理论框架基础、希望整体理解 v3.0 的终端用户而设。**如果你是初次接触 v3.0 的用户,直接读使用指南即可,不需要读这份主文档。**)

### 你不需要读完这份文档才能开始

v3.0 的训练**不要求用户先理解整个架构**。你可以从任何一个工具或一个模块开始——后续会自然了解其他部分。

但如果你想**整体理解你正在做什么**,这份主文档能给你:

- v3.0 的整体形态:双入口、三层结构、四大模块的结构关系
- 你当前在做的工作(比如工具 C / 模块一)在整体里的位置
- v3.0 不做什么、为什么不做(比如为什么 4.6 信念释放不在 v3.0 范围)
- v3.0 的元规则(为什么不存在"练完",为什么悖论是正常的,为什么任何升起的都可以作为新对象)

### 你最值得知道的几件事

**1. v3.0 不是理论框架的全部实操化**

理论框架是一份完整的理论框架,涵盖很多内容。v3.0 只在"减少反应模式"这一个核心轴上工作。理论框架中的一些重要章节(比如 4.6 潜意识信念释放、5.x 重建层的多数章节)**不在 v3.0 范围里**。这不是疏漏,是边界。

如果你的工作需要深入信念层,需要找水老师做一对一,或者直接读理论框架的对应章节。

**2. v3.0 没有"练完"**

v3.0 是螺旋的——同一个核心反应模式可能要被反复识别、穿透、选择多次,每次释放一层。**"我练完了"在 v3.0 里没有定义**。

但有真实的"告一段落"——某一层、某一具体反应模式真的有了变化,这是认可的。详见元规则文档第三章。

**3. v3.0 不是任务清单**

工具 C 不是日记打卡,模块一二三四不是分级考试,工具 A 不是必须每次触发就用。v3.0 的所有"训练"都允许中断、重启、按自己的节奏。

**做训练时身体的质感(松还是紧),比做了多少更重要。** 这是 v3.0 元规则第一条。

**4. v3.0 有两条路径,不是一条**

模块一二三是事后路径(觉察主导)—— 反应模式发生了之后的工作。模块四是前置路径(建设主导)—— 反应模式还没被外部触发之前的内在结构建设。两条路径不互相替代,各有适用场景。

如果你的核心诉求是"不被外部消极话术影响",模块四是给你的;如果是"看清楚我反应模式的根",模块一二三是给你的。大部分人两条都需要。

**5. Agent 的角色是协助,不是教练**

在任何对话助手中进行 v3.0 工作时，助手不会：

- 替你做识别 / 穿透 / 选择 / 建设
- 给你阶段评分
- 催促你"练得更勤一点"
- 把每句话都诊断分类

Agent 会:

- 在你需要时帮助看见
- 卡点时机制层面的解释
- 防滑陷阱时拉回
- 月度回看时帮你整理材料

如果你感到 agent 在"教练化"你,可以直接说——v3.0 的设计就是反对那种姿态的。

### 你不需要做的事

- **不需要按顺序读所有 v3.0 文档** —— 文档是参考,不是教材
- **不需要追求"完整执行 v3.0"** —— 完整执行本身是悖论的发作
- **不需要每次都从主文档查找你在哪一层** —— 你在做就是在做,不需要持续定位
- **不需要把 v3.0 当成"我的项目"** —— 它是工具,不是身份

## 十、v3.0 的克制

v3.0 是一套**克制的实操系统**——它不试图涵盖理论框架的全部,只在"减少反应模式"这一个核心轴上做扎实工作。

它的克制体现在:

**觉察主导路径的克制:**

- **不扩散** —— 严守核心轴,即使有价值的内容也不纳入
- **不诊断** —— 不给用户贴临床式标签
- **不评分** —— 不让训练变成 KPI
- **不催促** —— 允许用户按自己的节奏
- **不替代** —— 不替代水老师一对一工作,不替代专业心理治疗
- **不假装"练完"** —— 但承认真实的"告一段落"

**建设主导路径的克制:**

- **不假装"刀枪不入"** —— 模块四给的是大部分时候不被自动覆盖 + 被影响后能回来,不是"永远不被影响"
- **不让"反复练习"变成新的批评者** —— 漏一天就漏一天,做得简单就简单
- **不让"内在结构"变成新的身份** —— "我是个内在稳定的人"是身份化(撞模块四防滑三)
- **不在错位场景启用** —— 峰值期不引模块四,模块二未到位不引模块四,清单外诉求不引模块四
- **不为了用户诉求扩散范围** —— 模块四只覆盖建设工作清单内的特定场景

**两条路径的共同底线:**

- **不变成新的批评者** —— 任何工具/模块都不能变成新的反应模式驱动力
- **不变成挖掘项目** —— 穿透是为了流动,不是为了完成内在考古
- **不变成完美主义训练** —— 做得"不完美"本身可以是工作
- **不让两类工作混淆** —— 觉察是觉察,建设是建设,不机械套用错配处理

v3.0 还在演进。
