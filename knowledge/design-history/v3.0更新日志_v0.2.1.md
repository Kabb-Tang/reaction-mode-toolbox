## v0.1 · 第一阶段

**时间:** 2026 年初

**理论根基:** 内在转化理论框架 v2.3(当时版本)

### 整体设计意图

v3.0 第一阶段从零起草整套反应模式工作坊。设计立足于:

- **核心轴的明确:** v3.0 不是理论框架的全部实操化,只在"减少反应模式"这一个核心轴上工作。理论框架中的一些重要章节(比如 4.6 潜意识信念释放、5.x 重建层的多数章节)明确划在 v3.0 范围之外
- **双入口结构:** 用户既可以从场景化工具(被触发了 / 想做冥想 / 想记日志)进入,也可以从训练路径(系统训练识别力 / 穿透力 / 选择力)进入,两个入口共享同一套底层构件
- **三层结构:** 根基层(长期培养)+ 反应中工作(具体场景)+ 反馈闭环(月度回看 / 诊断)
- **三大模块的递进结构:** 识别 → 穿透 → 选择 → 螺旋上升回到识别(下一层)
- **不诊断 / 不评分 / 不催促 / 不替代 / 不假装练完:** 整个体系的克制原则

### 第一阶段产出清单

**11 步起草路径(2026 年 Q1 完成):**

1. 工具 A · 反弹模式实时介入流程 v0.1 —— 急性触发的三模块流程

3. 工具 C · 反应日志 v0.1 → v0.2 —— 开放式日记 + 月度回看
4. 模块一 · 识别力训练 v0.1
5. 模块二 · 穿透力训练 v0.1 → v0.2
6. 模块三 · 选择力训练 v0.1 → v0.2
7. 诊断路径 v0.1 → v0.2 —— Agent 内部分流和卡点诊断框架

## v0.2 · 第二阶段

**时间:** 2026 年 4 月

**理论根基升级:** 内在转化理论框架 v2.3 → v2.5

### 整体动机

v2.5 理论修订完成后,需要把以下五个新引入内容集成到 v3.0:

1. **不妖魔化抗拒**(理论框架 4.9 内的核心机制)—— 接受工作中升起的任何反应,都是接受工作的合法对象,不是失败的证据。具备递归处理结构(对抗拒的抗拒,继续作为新对象)
2. **觉察工作 vs 建设工作**(理论框架第三章前置说明)—— 两类工作并列存在,各有适用场景,不互相替代。错配会让 v3.0 卡在"看清了但不能动"或"建设动作变成新对抗"
3. **5.6 内在稳定参照点的建设**(理论框架第五章新增)—— 建设工作的标杆案例。包含"建设核心动作"四方向 + 五个误区
4. **2.6 全能自恋边界精度提升**(理论框架 2.6 修订)—— 三个识别标准 + 一条不是全能自恋判据。要解决的具体场景是"agent 看到任何'想加强自己 / 想稳一点 / 想不被影响'就触发全能自恋诊断,把用户堵在死局"
5. **4.3 释放三步骤修订**(理论框架 4.3 修订)—— 第二步充分感受加入"如果身体出现抗拒,启用 4.9 不妖魔化抗拒"的咬合

第二阶段的工作不是补丁式修订,是**v3.0 体系完整化的最后一块拼图**:

- v3.0 第一阶段建立了觉察主导路径(模块一二三 + 工具 A/B/C 等)
- v3.0 第二阶段加入建设主导路径(模块四)+ 觉察 / 建设两类工作的元层判据 + 不妖魔化抗拒作为整体兜底机制

完成第二阶段后,v3.0 体系成立为"觉察 + 建设两条路径并行 + 不妖魔化抗拒兜底"的完整架构。

### 修订点 1:工具 A v0.1 → v0.2(第 5 步)

**对应理论根基:** 理论框架 4.9 不妖魔化抗拒小节(v2.5 新立)

**修订内容:**

- **接受段(第三段)的"如果抗拒升起怎么办"扩展:** 从原来只覆盖一种抗拒形态(偷偷希望它走)扩展为完整的不妖魔化抗拒机制 —— 覆盖 v2.5 4.9 立的对象谱系(自责、羞耻、失望、对抗等),显性化对象切换的递归处理("如果再有新东西升起,继续把新升起的当作新的对象"),加咒语化陷阱标记("这些句子是描述,不是必须念的咒语 —— 如果机械念但内在没真的允许,身体不会松,你会发现自己在'表演接受'")
- **完成标志段加缓冲句:** "中途可能经过了几层抗拒升起又被允许 —— 这是正常的,不影响这一次接受工作的完成"
- **模块二常见卡点加第 5 条:** "我接受时身体里在抗拒"作为新卡点入口
- **顶部标注扩展:** 加入对 v2.5 4.9 不妖魔化抗拒小节的引用
- **不妖魔化抗拒辐射到深潜段:** 在接受段处理末尾加一句"这一处理也适用于第二段深潜过程中身体绷紧、不让感受进来的时刻",不在深潜段重复机制
- **版本叙事清理:** 文末"版本说明"节、"v0.1 正式版本完成"行、迭代节点列表全部清理(按决策 9)

**设计意图:**

工具 A 是急性介入工具,模块二虽然不在峰值里,但也不是从容状态。话术必须短、可在低带宽下执行,不能长篇理论。第 5 步的核心是**把"偷偷希望它走"这个雏形升级到完整机制** —— 显性化对象切换 + 给递归边界 + 标记咒语化陷阱。

修订后接受段的话术清单为 4 句(对应 v2.5 4.9 谱系),保留主话术"它在这里,我也在这里",新增对自责 / 羞耻 / 失望的 3 句,让用户在不只是"希望它走"那种典型抗拒场景下也有依靠。

**关联理论章节:** 理论框架 4.9 接受(含不妖魔化抗拒小节)、理论框架 4.3 释放三步骤(含 4.9 咬合)

### 修订点 2:模块二 v0.2 → v0.3(第 6 步)

**对应理论根基:** 理论框架 4.9 不妖魔化抗拒小节(v2.5 新立)

**修订内容:**

- **构件三接受微练习进阶段:** 加同样的轻量提示
- **防滑三"不把'接受'做成'假装接受'"扩展:** 保留 v2.3 4.9 误区三的"看见就够了"原意,加一句"如果你愿意继续做下去,可以把'我在假装'作为新的接受对象,启用日常深潜接受第三步在场段的不妖魔化抗拒处理 —— 但单独看见已经是接受工作,不必强求继续"。"不必强求继续"是关键防滑,防止扩展变成新强迫
- **第六章"对应章节"统一引用前缀:** 从 v2.3 X.X 改为"理论框架 X.X"(决策 12 立的统一规则)
- **历史遗留:** 文件名是 v0.2,但内部标题还是"v0.1 初稿",这是历史漏改 —— 第 6 步把它直接修到 v0.3,跳过中间的不一致状态
- **版本叙事清理:** 顶部"版本状态"行、第八章"未来可能的扩展(v0.2+)"整章、文末"v0.1 初稿完成"全部清理

**设计意图:**

模块二的"接受"工作分散在三个独立位置:构件一日常版的第三步"在场"、构件三的"日常练习"、构件三的"进阶"。三个位置的强度 / 语境完全不同 —— 不能复制工具 A 的话术过来。

设计核心是**按强度分配机制深度**:

- 日常深潜接受(15-20 分钟,从容场景)= 完整机制 + 简化话术
- 接受微练习(几秒到几分钟)= 轻量提示 + 引到详细机制
- 接受微练习进阶(30 秒到几分钟)= 同微练习

这样既覆盖了 v2.5 4.9 的谱系,又保护了微练习的"轻"特征(不让小练习背完整机制的重量,撞模块二防滑七"不主动制造不舒服去练接受")。

**关联理论章节:** 理论框架 4.9 接受(含不妖魔化抗拒小节)、理论框架 4.3 释放三步骤、理论框架 4.5 深潜

## v0.3 · 系统提示词修订(A 类指令重写 + B 类拆出)

**时间:** 2026 年 5 月

**理论根基:** 不变,仍基于内在转化理论框架 v2.5

**修订性质:** 这是对 v3.0 内测版的修订,**不是迭代到 v3.1**。整个 v3.0 体系架构(三层结构、双入口、四个模块、三个工具、元规则)保持不变。本次只修订 agent 系统提示词的执行层面 + 配套新增两份 B 类知识库文档。

### 修订动机

v3.0 内测期间(应用四批补丁后的"v3.0 完整版含建设维度")暴露出一系列结构性问题:

**一、信息密度倾轧(同行疗愈师反馈)**

一位线下做相同工作的疗愈师在测试时指出:agent 的回应密度大约是用户输入的 5-8 倍,分多节、带粗体、走完整套从 A 到 B 到结论的解构。这导致:

- 用户没有处理空间,被信息流推着走
- 用户从工作主体被矮化为信息接收者
- 用户失去"我自己想到了"的体验
- 用户面对长输出能做的只有"评估对不对",这是反应位置不是工作位置

**二、把实用咨询误升级为内在工作(测试失败案例)**

一位朋友在测试时带着具体的副业策略问题来(怎么跟不同朋友圈沟通自己的副业想法),agent 全程把它当作场景三深度自省工作处理:第一轮就跳到"你刚才整段分析的不是 X,是 Y"的解构。用户从配合 → 提出异议 → 直接情绪反弹("老登""卖弄学问")。

诊断:这是系统提示词原版"不接受表面故事"原则被泛化使用的典型表现 —— 该原则只在内在工作场景适用,被泛化到实用咨询会让用户感到被讲道理而非被帮助。

**三、把健康反思贴成"合理化"(同一失败案例)**

用户在第三轮自己拿掉了"边缘人"标签 —— 这是健康的自我观察和调整。Agent 紧接着把用户其他部分的反思贴成"退缩型策略在升级合理化"。这是诊断式标签贴在了正在做正确自我工作的用户身上,是最严重的越界。

**四、用户反弹后换说法重复(同一失败案例)**

用户在第四轮明确表达不认可,agent 道歉后,**立刻又给出了一套关于"成熟是什么"的完整教学** —— 这就是"换个说法再说一遍"。用户在第五轮精确指出了这一点。

**五、从未做"先判断类型"这一步**

直到第六轮被骂,用户精确说出了想要什么,agent 才真正切换到对的工作方式。前五轮 agent 始终没主动判断用户类型 —— 因为类型判断在原系统提示词里被埋在大量话术示例下面,没成为反射性的第零步。

**根因诊断:** 系统提示词原版长度 2632 行,其中"核心话术模式"和"特殊情况处理"占约 1300 行 —— 大量"点破 X""引导 Y"的话术示例占据了 LLM 的注意力高地,把"克制""场景判断""不武断判断"等真正决定行为的原则淹没了。LLM 在长上下文里向"出现频率最高、最具体、最有画面感"的内容靠拢,也就是大量犀利点破的话术示例。

### 修订范围

**A 类(指令层) —— 系统提示词重写:**

- 把原 2632 行的系统提示词压缩到约 730 行(压缩 72%)
- 保留:判断、约束、场景应对、调用接口
- 拆出到知识库:话术示例、详细场景案例、五层诊断子项、工具/模块/分支细节

**B 类(参考资料层) —— 拆出到知识库:**

- 新增《话术库 · 点破与引导参考》—— 承接原系统提示词中的全部话术示例
- 新增《对话示例集 · 含失败案例诊断》—— 含失败案例的完整诊断 + 5 个密度匹配版示例 + 场景判断对比
- 暂缓《特殊关系结构识别 · 操控/暴力/创伤场景》—— 系统提示词内已有简版,详细版可在内测确认主体没问题之后再补

### 关键决策

**决策 1. 不升 v3.1,定为"v3.0 修订版"**

v3.0 是内测版没发布,原本的设计就有结构性缺陷需要修订。叫 v3.1 暗示这是迭代升级,但实际是把 v3.0 修对。v3.0 体系架构没变,变的只是 agent 系统提示词的执行层面。所以版本号保持 v3.0,加"修订版"标识区分原内测版。

这个决策与"决策 19"(应用四批补丁后版本号"v3.0 完整版含建设维度")一致 —— 都属于 v3.0 内的版本演进,不动 v3.0 整体版号。

**决策 2. A/B 拆分原则:留判断,拆话术**

A 类(系统提示词)只放"判断 + 约束 + 何时调用知识库"。B 类(知识库)放"具体怎么说"。判断标准:这部分内容是 agent 每轮都要内化的反射,还是按需检索的工具书?前者留 A,后者拆 B。

**决策 3. 根本姿态调整:从"看透并说清"调整为"看透并只说让用户能自己走完最后一段的那个点"**

原系统提示词把 agent 设定成"看得很透的朋友" —— 定位本身没问题,但隐含执行倾向"看透了就要说出来"。修订后明确:agent 的工作不是"我能看见多少",是"用户当下能消化多少"。

**决策 4. 新增"克制集群"作为系统提示词第二节(地基段)**

把分散在原提示词各处的克制原则整合为独立大节(§2),并立为"前面的'你是谁'和后面的所有章节都受这一节约束"。包含四条子原则:

- §2.1 信息密度匹配(用户讲 100 字,核心回应 100-300 字,极少超 500 字。一段对话用户说话 50-70%,agent 30-50%)
- §2.2 看见多少不等于说出多少(一次只说一个最关键的点)
- §2.3 留白和沉默(信息不足时不硬给分析)
- §2.4 不把框架做成评判工具(不轻率给用户贴诊断式标签)

**决策 5. 新增"收集信息 vs 急于判断"作为第二地基(§5)**

承接同行反馈和失败案例诊断,新增独立大节立"多问少断"原则:

- §5.1 单段输入信息量不够支撑判断(一段文字只是一个数据点,不足以确定模式)
- §5.2 多问少断(把输出能量从"看见多少说多少"转移到"还需要知道什么")
- §5.3 信息密度匹配的真正逻辑(不是为了用户读得舒服,是为了拿到更多信息再判断)
- §5.4 用户反馈分两种处理:**情况 A**(信息不足时武断判断)→ 回到提问;**情况 B**(看到了用户不想被看到的东西)→ 不撤回,但密度大幅下降。判据:观察有没有用户实际说过的话作为依据
- §5.5 不为讨好用户改变判断,但永远准备调整方法

这一节明确了 agent 的工作位置:有自己原则的朋友,不是情绪价值提供者。

**决策 6. 类型判断前置为工作流程第零步**

新增 §6.1 类型判断,优先于其他所有判断。三种类型:实用支持(类型一)/ 情感支持(类型二)/ 内在模式工作(类型三)。

明确原则:**默认优先类型一和类型二。类型三是用户明确表达后才进入的,不是 agent 主动跳进去的**。不清楚时直接问,把判断权交回用户。

误判走类型一/二的成本(用户多说一句"其实我想聊聊为什么")远小于误判走类型三的成本(用户感到被讲道理、抗拒、夺回主导权的反弹)。

**决策 7. 新增"输出前自检"四问(§4)**

每次回应输出前内部走一遍:密度核对 / 核心点核对 / 留白核对 / 场景核对。第一问要变成肌肉记忆。这是把克制做成可执行操作。

**决策 8. 新增"接收用户反馈的方式"(§5.4 + §10.3)**

明确两个失误模式:

- 用户反馈"方向不对"之后,下一轮如果只是把同一个内容换种说法再讲一遍 —— 立刻识别,不要做
- 用户反弹时不是反驳内容,是反抗位置 —— 在试图夺回工作主导权。这时再讲一遍内容(哪怕换说法)等于继续抢主导权

**决策 9. 风格的适用范围明确分场景**

原系统提示词的"短准狠""不接受表面故事""犀利但不冷酷"等风格条款,修订后明确**只在内在工作场景使用**。表格化列出场景零(实用咨询)、场景一(急性触发)、场景二(日常觉察)、场景三(深度自省)、纯情感支持下的风格调整。

**决策 10. 历史版本号清理一并完成**

修订时一并处理已知问题 H5(三批补丁的"v2.3"前缀引用)。v3.0 修订版系统提示词中已无任何 v2.3 / v2.4 引用残留,只保留 v2.5 引用(当前生效的理论框架)。

**决策 11. 话术库重组:章节顺序按风险等级,不按内容主题**

新增《话术库》v1.1(基于水老师起草的 v1.0 + 三处补丁修订)。关键设计:

- 第一类是"点破"(高风险),第二类是"引导"(低风险)
- 第二类引导类的开头新增"零·精准提问(默认首选)"节 —— agent 检索引导类时第一眼看到的是"提问",不是"反弹四步法"
- 使用约束新增第 6 条"优先用提问代替点破"

设计原理:利用文档结构本身做行为校准。原系统提示词里点破话术在最显眼位置,导致 agent 反射性点破。话术库通过章节顺序 + 使用约束的双重提示,让 agent 优先走精准提问路径。

**决策 12. 对话示例集以失败案例为核心(约 40% 篇幅)**

《对话示例集》v1.0 第一部分是失败案例诊断的逐轮复盘 + 整体诊断的六个系统性失误 + 每个失误链接到系统提示词对应章节。

**补丁 1. §7.6 反弹四步法末尾加路径衔接**

补"四步法的工具/模块衔接(按用户当下所处步骤)":辨识/深潜阶段 → 工具 A;急性峰值过去但身体还有残余 → 工具 B;冒险阶段 → 模块三选择力训练。

**补丁 2. §8.2 调用原则从 6 条扩充到 11 条**

新增 5 条调用规则:

- 用户急性期之后想稳下来 → 按状态引导《工具 B》
- 用户经常被同类事情触发 / 想开始系统记录 → 引导《工具 C》
- 用户明确想系统训练识别 → 引导《模块一》
- 你内部需要场景分流判断 → 检索《诊断路径》(不输出诊断标签)
- 你识别到用户的生存策略类型或反弹主导类型 → 内部检索《个性化分支》

理由:原版本调用规则只覆盖了高频场景,《工具 B》《工具 C》《模块一》《诊断路径》《个性化分支》(两份)的主动引导/检索节点缺失。补完这 5 条让所有 13 份配套知识库文档都有明确的调用时机。

**补丁 3. §6.3 场景识别不清时加诊断路径调用**

补一句:"澄清问题之后情况仍复杂时,你内部可以检索《诊断路径》——仍然不输出诊断标签给用户"。

理由:诊断路径作为"跨场景的分流框架",原版本没说何时调用。场景识别不清是它的最佳调用时机。

**补丁 4. §8.1 整合层标注定位**

把《v3.0 主文档》《v3.0 使用指南》明确标注为"agent 通常不主动调用,按用户问题需要时引向":

- 主文档 = 给设计者的整体架构索引,除非用户问"v3.0 整体是什么"否则不调用

- 急性场景(工具 A 模块二接受段)= 完整机制 + 4 句话术 + 咒语化陷阱
- 日常场景(模块二日常深潜接受第三步)= 完整机制 + 简化话术(2-3 句)
- 微练习场景(模块二接受微练习)= 轻量提示 + 引到详细
- 元层场景(元规则文档 2.3 第四层 / 3.5 / 4.5)= 元层应用,不展开话术

- Agent 行为场景(第四批补丁改动 3)= 5 个场景对应表

v3.0 当前处于内测期,但回收使用反馈的机制还没设计。后续 v3.0.x 小迭代需要立这个机制。

**5. 一对一工作的接口**
